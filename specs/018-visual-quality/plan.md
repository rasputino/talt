# Implementation Plan: Visual Quality

**Branch**: `018-visual-quality` (worktree branch `claude/018-visual-quality-5b054b`) | **Date**: 2026-11-24 |
**Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/018-visual-quality/spec.md`

## Summary

Make the world prettier without touching the simulation. The client renderer gains cascaded shadow
maps for the sun, a shared linear lighting include with tone mapping, softer baked AO, MSAA 4×, an
animated water shader with depth tint and shoreline foam, decorative bushes and rocks, an optional
12-minute day/night cycle with lit windows, and quality presets saved in the player settings. A new
voxel model pipeline reads MagicaVoxel `.vox` files with a reader written from the format
description (`Talt.Core.Meshing.Models`, GPU-free), meshes them greedily with AO at three detail
levels at load, and draws them with one instanced draw per visible (model, level). Model keys in a
validated `models.json` link object kinds to models, so stations and depots (feature 010) only add
data. The first original models are generated by a new tool, `tools/Talt.ModelGen`. Every effect is
switchable and its frame cost is measured automatically with `--measure-effects` and recorded in
`docs/ARCHITECTURE.md`. See [research.md](research.md) R1–R13.

## Technical Context

**Language/Version**: C# (latest) on .NET 10, WGSL shaders

**Primary Dependencies**: none new (Silk.NET WebGPU / wgpu-native already used; `System.Text.Json`
in-box).

**Storage**: embedded resources: `.vox` model files (`models/<name>.vox`), `models.json` and
`graphics-presets.json` (client data); player settings JSON gains a `graphics` object (version 4).

**Testing**: xUnit: `Talt.Core.Tests/Meshing/Models` (vox reader/writer round trip, malformed files,
axis conversion, greedy model mesh counts, AO, LOD downsampling); `Talt.Client.Tests/Rendering`
(shader include preprocessor, cascade fitting and texel snapping, model library validation, model
batch bucketing and culling, decoration determinism and exclusions, time of day, graphics settings
load/save/preset/custom, every shipped model key loads); WGSL validated by compiling shaders in a
`Category=Gpu` test; existing golden fingerprint tests unchanged; BenchmarkDotNet: model load and
mesh, instance bucketing (60 000 instances), decoration scattering.

**Target Platform**: Windows, Linux x64/arm64, macOS arm64 (Vulkan, Metal, DX12 through WebGPU).

**Project Type**: desktop game (Core library + client + headless tool + benchmarks + new generator
tool).

**Performance Goals**: High preset 60 FPS on a 2048 map, Medium preset 60 FPS on a 4096 map at
every zoom on the reference machine (SC-001/002); models load and mesh in < 1 s (SC-005); preset
switch within one second (SC-007); zero managed allocations per frame in steady state; model
bucketing < 1 ms for 60 000 instances.

**Constraints**: no simulation, map or fingerprint change (FR-021); `Talt.Core` stays GPU-free;
all new player text in English and Spanish; all art original; WebGPU guarantees only sample counts
1 and 4; integrated GPU shares memory with the CPU (keep per-frame uploads small, ≤ 2 MB).

**Scale/Scope**: up to 50 000 vehicles, ~30 000 visible town buildings, ~1 000 industries, 48 000
trees near the camera, up to ~40 000 decoration instances; ~40 model files; 3 detail levels; 1–3
shadow cascades.

## Design overview

### Frame

1. CPU prepare: terrain regions (camera), roads, town/industry/tree/decoration/vehicle instances into
   the `ModelBatch`; time of day → light; cascades fitted (R1); terrain shadow lists per cascade.
2. Uniform writes: main uniforms + one uniform buffer per cascade (`view_proj` = light matrix).
3. **Shadow pass** per cascade (when shadows on): depth-only into layer *k* of the shadow array:
   terrain, roads, models (and placeholder boxes).
4. **World pass**: MSAA colour + depth (or single-sample when AA off), group 0 = main uniforms,
   group 1 = frame resources; terrain (with water), roads, models, placeholders, highlights,
   translucent preview; resolve into the surface.
5. **UI pass** unchanged.

### Bind groups

- Group 0 (vertex + fragment): `Uniforms` — `view_proj`, sun direction/colour, sky and ground
  ambient, camera position + fog distance, sky colour, cascade matrices and splits, time, exposure,
  AO strength, flags (shadows, water, night factor), palette. Shadow pipelines use a layout with
  group 0 only, so the same vertex shaders serve both passes.
- Group 1 (fragment): shadow map array + comparison sampler, water texture + linear sampler, model
  palette texture. Rebuilt only when shadow settings or the world change.

### Feature 010 coordination

Stations and depots get models by adding `.vox` files and `station:<id>` / `depot:<id>` entries in
`models.json` and calling `ModelBatch.Add(key, variant, position, yaw, tint)` from their instance
source; until then their placeholder path (boxes) keeps working and still casts shadows. See
[contracts/model-pipeline.md](contracts/model-pipeline.md). Expected merge points: renderer
constructors (shared layouts), `GameWindow.OnRender`, localization files.

## Complexity Tracking

| Addition | Why needed | Simpler alternative rejected because |
|----------|------------|--------------------------------------|
| New tool project `tools/Talt.ModelGen` | The first original models are generated from code (clarification) and must be reproducible | Hand-writing binary `.vox` files or hard-coding models in the client mixes art with code |
| WGSL `#include` preprocessor | One lighting implementation for 8 shaders | Copy-pasting shadow/tone-map code into each shader invites drift |
| Pipelines per sample count | MSAA can be switched without restarting (FR-016) | Restart-only AA contradicts the immediate-apply requirement |
| Two pipeline layouts (main / shadow) | Shadow passes cannot bind the shadow texture they render into | A dummy texture per pass would duplicate every bind group |
